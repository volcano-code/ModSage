# v0.3 冻结检索评测

日期：2026-10-21（北京时间）。本轮建立可离线复现的检索评测，比较 v0.2 关键词加权基线与 v0.3 BM25 排序。实际语料和标签分别见 [catalog.v1.json](../eval/catalog.v1.json)、[queries.v1.json](../eval/queries.v1.json)，完整逐题结果见 [results.v1.json](../eval/results.v1.json)。

## 评测对象与数据来源

数据集标识：`workshop-excerpts-20261020-v1`。

- 从 2026-10-20 已同步的真实 Steam Workshop 目录中选择 **42 个条目**，覆盖派系兵种、英雄、外观、界面、战役、战斗和大修，以及信息不足条目。
- 每条保存原始标题、标签、短摘录、采集时的分类和中文支持状态、对应 Workshop URL、观察时间与内容哈希。
- 摘录经过有界截取。标题、标签和摘录合计最多 25 个保守词单元；汉字按单字计数。没有复制完整作者说明、原始响应或数据库。
- 排序只使用标题、标签和短摘录，不将标签理由、原始内容哈希或预期答案作为检索输入。
- 全部记录的 `chinese_support` 保留采集时的 `unknown`。中文标题、中文摘录或汉化条目名称不会自动升级为已验证游戏内中文支持。
- 这些记录只由离线脚本加载成内存对象，不执行导入、不创建数据库，也不是生产应用的默认种子数据。

短摘录与生产目录的完整作者介绍并不相同，因此分数仅描述这份冻结集合。它不能代表整个 Workshop，也不能替代真实用户需求上的评测。

## 查询与标签

共 **28 条查询**：14 条 `development`、14 条 `regression`。其中 25 条有已标注相关结果，3 条为无答案。

查询包含中文、中英混合和英文，覆盖指定派系、精确名称、内容类型、排除大修、保留原版兵种、必须汉化、无来源覆盖，以及两条中文改述难例。9 条查询另有独立记录的禁入条目列表，用于检查已知的派系或内容排除条件。

标签根据条目名称与作者说明在首次跑分前编写并冻结：

| 字段 | 含义 |
| --- | --- |
| `qrels` 中的 2 | 直接符合查询意图的条目 |
| `qrels` 中的 1 | 有关联但不如直接结果准确的条目 |
| 未在 `qrels` 中列出 | 在本集合中按 0 分处理；不表示经过穷尽标注 |
| `forbidden_ids` | 独立记录的硬排除样例；不从排序结果反推 |
| `expected=no_answer` | 冻结语料或事实状态不足以确认结果 |
| `rationale` | 标签的简短判断依据，不进入检索特征 |

这些是开发期判断，**尚未经过独立人工复核**。`regression` 是固定回归覆盖，不是未被开发者查看的统计留出集。语料选择、查询规模和开发期标注都限制了结论的外推范围。

## 比较方法

两种方法读取同一份语料，使用相同的 `parse_rules` 与 `is_eligible` 先处理硬条件。这样可以比较排序机制，同时另外用独立的 `forbidden_ids` 判断已知禁入条目是否出现在前 5 项。

| 方法 | 实际执行 |
| --- | --- |
| `legacy_keywords` | 保留 v0.2 `search_terms`、`candidate_score`、中文软偏好加分和降序 ID 同分规则 |
| `bm25` | 使用 v0.3 `rank_bm25`；中英分词及既有领域词别名扩展，按标题、标签、作者短摘录分字段排序 |

评测不读取模型配置，不调用 LLM 或 embedding 服务，不使用随机向量，不把固定相似度夹具当成模型效果。`engine=rules` 与检索算法是不同维度；这份报告只比较无模型解析下的两个词法排序方法。

## 指标口径

所有排序指标截止在前 5 项，先对每条有答案查询计算，再做宏平均。3 条无答案查询不参与 Recall、nDCG、MRR 平均，也不会被记为满分来抬高指标。

- **Recall@5：**前 5 项命中的已标注相关条目数，除以该查询全部已标注相关条目数。
- **nDCG@5：**相关度收益为 `2^grade - 1`，位置折扣为 `log2(rank + 1)`，除以按标签排序得到的理想 DCG。
- **MRR@5：**第一条已标注相关结果的排名倒数；前 5 项没有相关结果时为 0。
- **无答案准确率：**3 条无答案查询中，返回空列表的比例。
- **硬条件违规数：**前 5 项命中独立 `forbidden_ids` 的数量，仅覆盖这些已标注样例，不能代表所有可能的约束。

实现会拒绝重复结果 ID、重复 JSON 键、未知 qrel ID、相互矛盾的相关/禁入标签，以及数据文件或特征哈希不一致。

## 实际结果

以下结果由冻结数据直接执行生成，**没有为 BM25 修改标签或摘录**：

| 范围 / 方法 | Recall@5 | nDCG@5 | MRR@5 | 无答案准确率 | 禁入违规数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 全部 · 旧关键词 | 0.9200 | 0.8753 | 0.8733 | 3 / 3 | 0 |
| 全部 · BM25 | 0.9200 | 0.8900 | 0.9000 | 3 / 3 | 0 |
| development · 旧关键词 | 0.9167 | 0.8646 | 0.8611 | 2 / 2 | 0 |
| development · BM25 | 0.9167 | 0.8915 | 0.9167 | 2 / 2 | 0 |
| regression · 旧关键词 | 0.9231 | 0.8852 | 0.8846 | 1 / 1 | 0 |
| regression · BM25 | 0.9231 | 0.8885 | 0.8846 | 1 / 1 | 0 |

在这个小集合中，BM25 的首位与前列排序略有改善，召回率保持不变；不能据此宣称普遍优于其他检索系统。

具体观察：

- `q01`“震旦将领卫队坐骑”中，直接对应的中文卫队条目由第 4 位升至第 1 位；英文版本仍未排在紧邻位置，说明跨语言词汇覆盖仍有限。
- `q10`“大修 Radious Part 1”仍有同系列条目排在第一部分之前，精确名称与版本序号匹配尚可继续改进。
- `q14`“爆炸摧毁战场树木”和 `q28`“让弓箭手边走边射时分散目标”两种方法都未召回。它们对应英文作者说明，现有词法别名不足以覆盖中文改述。这是后续真实 embedding 评测应处理的缺口，不能用本轮结果声称已经解决。

## 复现与 CI

完成后端安装后，在仓库根目录执行：

```bash
.venv/bin/python scripts/evaluate_retrieval.py \
  --check --output artifacts/retrieval-evaluation.json
```

脚本只读取冻结文件，输出汇总到终端，并保存逐题结果、两个文件的 SHA-256、解析条件和排名。默认关闭计时，因此在相同实现下输出可重复比较。支持 `--k 1..20`；本报告固定 `--k 5`。

CI 使用同一命令的 `python` 版本。`--check` 会在数据不完整、禁入条目出现或无答案样例被填充时失败。它不会在看到本轮分数后挑选一个方便通过的排序质量阈值；Recall、nDCG 和 MRR 始终完整报告供审查。

如需查看一次本地纯排序耗时，可额外传入 `--timing`。这些数字不包含数据库、API、网络、LLM 或 embedding，不代表生产吞吐、端到端延迟，也没有经过多次负载基准测量。

新增的 13 条自动化用例验证手算指标、无答案统计口径、重复结果和 qrel 拒绝、数据哈希与标签一致性、相同硬筛选候选输入、独立禁入标签，以及确定性和离线边界。本轮这些用例已全部通过。
