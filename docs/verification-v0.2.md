新增后端用例验证唯一键与参数冲突、多连接竞争、不同任务单目录互斥、过期恢复、旧 owner 无法提交、续租跨过初始租约、有限重试和耗尽、上海日期调度、空来源不破坏已有目录、部分数据语义、请求预算取消、模型次数控制、进程心跳与公开状态。

独立审查通过真实 `SteamClient` 与 HTTPX MockTransport 复现并修复了一个重试缺陷：仅存发现 ID 会丢失 QueryFiles 留在客户端内存中的分类与前置元数据。当前在导入未提交时重新执行有界发现，导入提交后才从后续阶段恢复。回归测试保留这一场景。

E2E 连接实际 API 和隔离 SQLite 数据库，覆盖搜索与详情、负向条件推荐及记录持久化、收藏重载、缺失前置、链接导出、明确空状态/失败状态、代理安全边界、新同步状态路由，以及移动端完整操作链。合成 fixture 只进入显式启用的 `modsage-e2e.db`。最终 WebP 资源接入后重新完成生产构建和全部 7 条 E2E（9.7 秒）；首页用例同时确认主视觉图片实际加载完成且具有有效像素宽度。

- 已检查的五个页面均无 JavaScript 页面异常或水平溢出。
- 本轮截图中的实际图片均成功加载；首页背景是项目原创生成插画，模组图片来自对应作者的 Workshop 预览。

## PostgreSQL 与容器验收

本轮 CI 扩展真实 PostgreSQL 验证：4 个连接同时入队同 key、4 个 worker 竞争领取、模拟租约过期接管、拒绝旧 owner 心跳与成功提交。Docker Compose 验证数据库、API、前端连通性，以及可选 worker 的空队列单次启动；CI 不请求真实 Steam 或模型服务。

本地环境没有 Docker daemon / PostgreSQL 服务，以上环境的通过状态以 [本次提交的 GitHub Actions](https://github.com/volcano-code/ModSage/actions/workflows/ci.yml) 为准。测试和配置存在不等于已经运行通过；发布说明会记录实际远端验收结果。
