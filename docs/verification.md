# v0.1 验证记录

验证日期：2026-10-20。以下区分真实外部调用、隔离集成测试和仍未验证的能力。

## 真实 Steam 数据

- 明确选择公共 Workshop 页面有限发现，取得 50 个候选 ID。
- 官方详情接口返回 49 个通过游戏、公开状态及 Mod 类型校验的条目；1 个不满足保守类型判定的条目被跳过。
- 导入真实本地数据库后，目录包含 49 条记录。其中 13 条具有足够中文原文，标记为 `source_chinese`；没有将这些摘录标为模型生成。
- 对相同 49 个 ID 再次执行同步：`created=0, changed=0, unchanged=49, imported=49`。
- 本批源响应没有完整前置关系字段，49 条均保留待核实状态。作者为 Steam creator ID，没有伪造显示名称。
- 实际页面从该数据库读取，未在产品中默认导入演示记录。

接口、字段覆盖与来源文档详见 [数据接入报告](data-access-report.md)。这次小规模实测不能证明全站覆盖或连续运行可靠性。

## 自动化与浏览器验证

使用锁定依赖，后端运行 Python 3.12，前端运行 Node.js 24。CI 同时使用 Node.js 22 验证受支持的最低大版本。

最终本地结果：**88 项后端测试通过，语句覆盖率 86%；6 条 Chromium 端到端用例通过。** 覆盖率不包含尚未执行的真实模型调用或游戏加载验证。

- 后端测试覆盖来源校验、传输重试、同步幂等、事务失败、摘要证据保留、来源变化失效、负向需求、模型失败退化、超时持久化、日报并发首建、管理员鉴权、输入边界和未知前置语义。
- Ruff 检查和格式检查、TypeScript 类型检查、ESLint、Next.js 生产构建通过。
- Chromium 集成测试连接真实 API 与独立 SQLite 数据库，验证搜索与详情、需求推荐、持久化推荐记录、浏览器清单、缺失前置、导出、明确空状态、明确失败状态、代理白名单及体积限制、移动导航。
- 测试用合成数据只能写入显式启用的 `modsage-e2e.db`，标题和说明都带有 E2E 标记。
- 真实 49 条目录的桌面与 390 像素移动端验收中，没有页面 JavaScript 异常或水平溢出。

真实数据复核发现并修复了作者简介末尾推广其他作品造成的派系误匹配。当前优先按标题、标签识别主要派系，正文仅使用前段并截断常见推广段落；明确“新增兵种/火炮”的请求增加内容条件，同时保留否定表达。在这批有限目录中，“帝国新增火炮和兵种、不要大修”返回 0 条并解释目录不足，“震旦新增兵种、不要大修”返回 4 条。没有为了凑数量放宽条件。这仍是保守的规则策略，可能漏掉只在介绍后段写明用途的 Mod。

最终测试数量及云端结果以 [GitHub Actions](https://github.com/volcano-code/ModSage/actions/workflows/ci.yml) 和本次交付说明为准；CI 上传 JUnit、覆盖率 XML、失败截图和浏览器报告。
